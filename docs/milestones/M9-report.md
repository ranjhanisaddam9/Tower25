## Part A: Short or over payment

- **Pills:** when an invoice is marked paid with an amount received different from its total, both the list and the invoice show a pill: "Short by $X" (warning) or "Over by $X" (info). Exact payments show nothing.
- **Pure rules** (`InvoiceMath`):
  - `PaymentDifference` = received − total (paid invoices only)
  - `OutstandingUsd` = the whole total while issued, the shortfall once paid short, else 0
  - `ExcessUsd`.
- **/invoices tiles:**
  - Outstanding = Σ unpaid totals + Σ shortfalls (its caption notes "includes N paid short").
  - A separate **"Received in excess"** tile appears when anything was overpaid.
- **Dashboard tile:** the same outstanding figure; its caption adds "N paid short" and "received in excess $X".
- **SPEC §7** gained the rule, with a change-log entry (2026-10-10, M9).
- **Tests:**
  - unit: short, exact and over; totals with unpaid, short, exact, over and void invoices; pill texts
  - integration: exact → short → over on two real invoices, with list, invoice and dashboard figures
  - the M8 overdue test now expects its $4.50 shortfall as outstanding.

## Part B: Export infrastructure

**Packages** (pinned in `Directory.Packages.props`):
- ClosedXML **0.105.0**
- QuestPDF **2026.8.0**, Community licence
- PdfPig **0.1.16** (tests only, for PDF text extraction)

The README has a new "Exports and third-party licences" section: the Community licence is free under USD 1M annual revenue.

**PDF font:**
- Plus Jakarta Sans Regular, SemiBold and Bold static TTFs, from the official repository (github.com/tokotype/PlusJakartaSans, `fonts/ttf`, sizes matched the repo listing), with `OFL.txt`.
- Stored in `src/HR.Infrastructure/Fonts`, embedded as resources and registered once at startup (`PdfSetup.Configure()`, called from `AddInfrastructure`).
- Missing-glyph checking is off, so a name in another script falls back to an installed font instead of failing the download.

**Shared builder** (`HR.Infrastructure/Exports/SpreadsheetBuilder`):
- **Typed cells:** money, days, rates, percent and integers are numbers with formats; dates are dates. Text is always a string value; ClosedXML never writes a formula.
- **Injection:** text starting with `=`, `+`, `-`, `@`, tab or CR also gets Excel's **quote prefix**, so editing it keeps it text.
- **Formats:**
  - USD `$#,##0.00`; PKR `"Rs "#,##0`
  - dates `dd mmm yyyy`; days `0.0`; rates `0.0000`; percent `0.00"%"`.
- **Layout:**
  - bold, frozen header row with an auto-filter;
  - widths computed from the content (no font measuring);
  - optional bold totals row.
- **Sheets:** each sheet is named after its report; every workbook ends with an **About** sheet: report, generated at (Asia/Karachi), generated by, rows, and every filter applied.

**Responses** (`HR.Web/Exports/Downloads`):
- `Content-Disposition: attachment`, with a safe ASCII file name from `ExportFileName` (letters, digits and `-` only), e.g. `payroll-2026-10-01.xlsx` or `T25-2026-0001.pdf`.
- `Cache-Control: no-store`, `Pragma: no-cache`, `X-Content-Type-Options: nosniff`.
- GET only; the same policies as the source page.

**Audit:** event **1700** records the user, report, format, row count and filters. It never records row contents. A search term is logged only as `Search=(given)`, because people search can match phone numbers.

**Masking:** CNIC and IBAN are masked in every export except the payroll register (Excel and PDF), which carries full IBANs for the bank upload. The people export masks them inside `PersonService`, so the full values never leave the service. Phones are exported as stored.

## Part C: Excel exports

Each page has an **Export** button. Its link is built from the filters the page actually applied, never the raw query string, so a Manager's page can't echo an Admin-only parameter. The integration tests caught exactly that in a first version.

| Export | Route | Manager | Admin adds |
|---|---|---|---|
| People | `/people/export` | code, name, type, designation, email, phone, CNIC (masked), bank, IBAN (masked), joined, leaving, status | hire source |
| Salaries | `/salaries/export` | monthly pay (USD and PKR columns), since, last change and % | billed, commission, earning per full period, review flag, totals |
| Absences | `/absences/export` (period with the page's filters, or `from`/`to` up to 1 year) | rows with paid/unpaid parts + **By person** sheet | — |
| Exchange rates | `/exchange-rates/export` | full history with change % | — |
| Payroll lines | `/payroll/{id}/export` | days, pay, adjustments, net pay, problem, totals | hire source, billed, adjustments USD, invoice, owner earning (USD/PKR) |
| Register (bank sheet) | `/payroll/{id}/register/export` | full IBAN, net pay PKR, total | — |
| Invoice (Admin) | `/invoices/{id}/export` | — | the invoice page's columns and total |
| Owner income (Admin) | `/owner-income/export` | — | the selected view's breakdown (+ draft columns when included) and a **Contributors** sheet |

Manager exports are built from the same Manager projections as the pages (`ListAsync`, `LinesAsync`, …). The billing columns come only from the separate Admin methods.

## Part D: PDF downloads (A4, QuestPDF)

**Invoice** (`/invoices/{id}/pdf`, Admin, `<number>.pdf`):
- built from the invoice's own snapshot;
- From / Bill to block and the facts (number, dates, period, status) once, at the top of page 1;
- the lines table, with its header repeated on later pages and rows never split;
- total, payment details and footer note;
- every footer reads "Invoice T25-2026-0001 · Page n of m";
- a void invoice carries a "VOID" watermark.

**Payslip** (`/payroll/{id}/lines/{lineId}/payslip/pdf`) and **All payslips** (`/payroll/{id}/payslips/pdf`, one page per person):
- from the frozen line data, laid out like the print page: issuer, period, person, days table, pay table, net pay, rate and USD reference;
- **no billing for any role.**

**Register** (`/payroll/{id}/register/pdf`): code, name, bank, full IBAN, net pay, total.

**Drafts:** payslip and register PDFs of a draft run carry a large light **"DRAFT – NOT FINAL"** watermark across the page, plus a red label in the header. Their file names end in `-draft`.

## Part E: Reports (`/reports`, both roles; the sidebar link is live)

**Hub:** four cards in a 2 × 2 grid (one column on phones).

1. **Payroll history:**
   - every finalized run with people and total net pay (PKR); Admins also see invoice USD and owner earning USD;
   - bar chart of net pay for the last 24 periods, plus an owner-earning chart for Admins only;
   - data table with totals; Excel export.
2. **Salary changes:**
   - increments and decrements effective in a date range (default: the last 12 calendar months);
   - columns: person, effective from, old → new pay, change % ("currency changed" when not comparable);
   - Admins also see billed and commission old → new, including billing-only changes;
   - Excel export.
3. **Absence summary:**
   - range of at most one year (enforced; error message on the page, toast on export);
   - per person: absent, paid leave used, unpaid, and one column per month;
   - totals row; Excel export.
4. **Headcount:**
   - each of the last 12 months: active at month end (today for the current month), split into employees and internees;
   - joiners = new employment periods (a rejoin counts), leavers = leaving dates up to that day;
   - stacked bar chart + table + Excel export.

**Charts:**
- server-rendered inline SVG with `<title>` / `<desc>` and the same numbers in a table;
- no style attributes and no JS; colours from theme tokens;
- on phones the labels are drawn larger and every other x-axis label is hidden when there are more than six;
- count axes use whole-number ticks.

**Data sources:** payroll figures come only from finalized, frozen lines. The domain rules are pure and unit-tested: `HeadcountCalculator`, `SalaryChanges` and `ReportRange`.

## Part F: Person "Payslips" tab

- Lists the person's lines in **finalized** runs, newest first: period, payable days, net pay (PKR).
- Each row links to the payslip page and its PDF.
- Drafts are never listed. No billing for either role (tested for both).
- Empty state: "No finalized payroll includes this person yet."

## Part G: Dashboard

- A **Payroll trend** card: a sparkline of net pay for the last 6 finalized periods, plus owner earning for Admins only (never queried for Managers).
- A text summary, e.g. "Latest finalized payroll (16–31 Oct 2026): net pay Rs 1,977,475; Rs 2,004,200 in 01–15 Oct 2026. Owner earning $2,597.81 in the latest period."
- A link to Payroll history.
- All existing tiles are kept. The dashboard fits at 375px (no overflow).

## Known issues and deviations

**No SPEC deviations.** SPEC §7 was extended for Part A, as the M9 prompt specified, and the change is in the change log.

1. **PDF text layer:** in the Plus Jakarta Sans glyph mapping, some extractors (PdfPig) return the second hyphen of "T25-2026-0001" as a minus sign (U+2212). The PDF renders correctly; only copy/paste of the number from some viewers may be affected. The tests normalise it.
2. A 24-line invoice needs 2 pages: the payment details move to page 2. Shorter invoices fit on one page.
3. Glyph checking is off for robustness: a name in a script the font lacks renders in an installed fallback font instead of failing.
4. Some downloads report `Cache-Control: no-cache,no-store` (the framework adds `no-cache` on authenticated responses). `no-store` is always present.
5. The salary-changes report accepts any range (only the absence ranges are limited to one year, as specified).
